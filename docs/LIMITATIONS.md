# Limitations

| ID | Limitation | Impact | Workaround |
|---|---|---|---|
| L-01 | Global `ptable.lock` is coarse-grained | Limits scalability on multi-core; fine for NCPU ≤ 8 | N/A for course scope |
| L-02 | One `setworkflow` per process | Process cannot change workflow after joining | Design choice; workflows are immutable per process |
| L-03 | Workflow table size fixed at NWF=8 | Maximum 7 concurrent workflows (0 is reserved) | Increase NWF in `sched_params.h` if needed |
| L-04 | Deadline miss detection is sampled at scheduler/exit boundaries | A process that remains outside those paths is marked on the next scheduler scan | Use scheduler and exit observations as the firm-deadline measurement points |
| L-05 | Donation uses an over-approximate holder scan and a benign race on `ofile` | A process can temporarily receive donation while it still has a duplicated writable descriptor | Donation is limited to pipes; close unused descriptors in tests |
| L-17 | Donation is only modeled through pipes, not `wait`, locks, or regular files | Other priority-inversion paths are not accelerated | Use explicit pipe pipelines for this stage |
| L-18 | Each donation event scans `NPROC * NOFILE` descriptor entries | Cost grows with the fixed process and descriptor-table sizes | Keep `NPROC` and pipe fan-out bounded |
| L-19 | Timer nondeterminism under QEMU TCG | Tick timing varies with host load; deadline misses may be non-deterministic | Record raw logs and repeat measurements |
| L-20 | Trace ring wraps and drops oldest entries | Ring capacity is fixed at 256 entries per CPU; long runs lose early events | Increase `TRACE_SIZE` in `sched_params.h` if needed |
| L-21 | `rdtsc` assumptions | Assumes invariant TSC across cores and no frequency scaling; may not hold on all hardware | Use tick-based timing as fallback for critical sections |
| L-22 | Trace ring uses `ptable.lock` for all writers | Coarse locking adds contention to scheduler/donation paths | N/A for course scope (NCPU ≤ 8) |
| L-23 | Some Stage 6 evidence requires manual QEMU execution | CPUS=3 and two-successful-workflow interleaving are environment/design-blocked | Use an xv6-compatible SMP QEMU setup and distinct workflow IDs before rerunning those cases |
| L-24 | This QEMU/xv6 environment reports one CPU despite `-smp 3` | CPUS=3 harness rows cannot be accepted as valid multi-core observations | Resolved in Stage 7. On QEMU 10.1.0 with the default machine type, QEMU creates 3 vCPUs (monitor `info cpus` lists #0-#2) but xv6 starts only cpu0, because the MP table it reads lists one processor. With `-machine pc-i440fx-yakkety` xv6 starts cpu0-cpu2 and `schedstat` reports ncpu=3. `host/config.json` `qemu_extra` carries the flag and the harness passes it. |
| L-06 | Admission control uses the configured slack and global urgent-process cap | It is not utilization-based admission control | Tune `MIN_SLACK` and `MAX_URGENT` in `sched_params.h` |
| L-07 | `last_run` counter can wrap | 32-bit counter wraps after 4B scheduling cycles | Negligible for practical runs |
| L-08 | `ticks` wrap-around handled only in `dl_before` | Other comparisons of deadlines may be incorrect if not using `dl_before` | Always use `dl_before` for deadline comparisons |
| L-09 | xv6 has no process exit status | The bridge can report sentinel completion or exec failure, but not child return codes | Emit explicit result text from guest tools |
| L-10 | xv6 shell input is limited to 99 characters | Long guest commands cannot be sent safely | Fixed templates and a command limit below 90 characters |
| L-11 | Serial/QEMU timing is approximate | Timeout and deadline observations vary with host load | Record raw logs and repeat measurements |
| L-12 | Concurrent user output can interleave character writes | A line from multiple processes may not be readable as one record | Guest tools should construct important lines before one write |
| L-13 | `@@DONE` reports process completion, not command semantics | xv6 has no exit status, so a command such as missing-file `cat` needs host-side output classification | Record both observation status and raw guest output |
| L-14 | Fork-inherited deadlines | A fork child inherits its parent's own deadline | Admission counts each live finite-deadline process; callers must account for inherited urgency |
| L-15 | `MAX_URGENT` is global | The cap is shared by all processes, not isolated per user | Treat it as a kernel-wide safety limit |
| L-16 | Firm deadlines hide late work from EDF | A missed process is changed to `NO_DEADLINE` and becomes best-effort | Miss counters and raw logs retain evidence of lateness |
| L-25 | Small n and collapsed bootstrap intervals | Cells have 20 runs (main batch) or 10 runs (sweep). The percentile bootstrap (10000 resamples, seed 20261104) collapses to a single point when a cell has 0 or n misses; this happens in 13 of the 21 cells in `results/summary.csv`. A point interval reflects the method, not certainty. | Report counts with the intervals; the Fisher exact test is two-sided and its note states that n is small |
| L-26 | QEMU TCG timing noise and run-order drift | edf at CPUS=1, α 3.0 missed 4/10 with mean finish 70.7. In the order check (`results/order_check.csv`, α 3.0 run before α 1.0), edf at α 3.0 finished 45, 45, 45, 46, 46, like α 1.0 (45-52). rr finish also rises at α 2.5 and 3.0 (means 53.3 and 59.7); in the order check rr at α 3.0 gave 49-59 against 45-49 at α 1.0, although rr never reads the deadline when scheduling. | The edf effect is attributed to run order and host drift late in the sweep; the rr rise is unexplained and treated as TCG noise. Data kept unchanged. |
| L-27 | Outlier miss under donation | edf_donate at CPUS=1, α 1.5, run 4 finished at 99 ticks, the only miss under donation in that cell; its log looks normal. The single edf_donate miss at CPUS=3, α 1.5 is run 18 (finish 38, deadline 37). | Hypothesis, not traced: after a kernel-marked miss, `effective()` returns `NO_DEADLINE`, donation stops, and the pipeline shares the CPU with the hogs. `host/plots/gantt-T58-miss.png` shows this in a separate run (finish 58): DONATE events stop at DEADLINE_MISS and the hogs then run. Data kept unchanged. |
| L-28 | Intermittent hang in `usertests` concreate | One rr `usertests` run after the fix (`logs/stage7-fix/usertests_rr_cpus1.raw`) hung in concreate with two processes sleeping on inode sleeplocks (`create->iput->acquiresleep` and `sys_link->dirlink->iput->acquiresleep`) | Not reproduced in 2 reruns; rr does not call `dl_before`. The cause is open. |
| L-29 | Missing post-fix CPUS=3 donation-test log | A CPUS=3 donation-test run after the fix was not saved, and in that run `cycletest` printed no `donate: cycle` line. Post-fix cycle detection on CPUS=3 is therefore not evidenced. | Rerun the donation tests on CPUS=3 with the machine flag and keep the log |
| L-30 | Trace ring wrap in the T-58 traces | `TRACE_SIZE` is 256 per CPU. The T-58 figure uses the second of two `schedtrace` dumps from one run, extracted as the last 256 trace lines; seq 0-162 are lost. The miss run (`T58-edf_donate-trace-clean.raw`) also wrapped. The T-57 trace (207 events) is complete. | The original log is kept unchanged next to the extracted file; the extraction is stated in `EVIDENCE_INDEX.md` |
| L-31 | Kernel miss counter and deadline anchor | `RESULT miss=` is `global_misses`, cumulative since boot and never reset. The kernel workflow deadline is set when the final stage calls `setworkflow` (now + deadline), later than `wfgen`'s start, which is taken before forking. Example: the T-59 rerun finished 27 < 37 but reported miss_kernel=1 because the pilot's miss in the same boot was still counted. | The host computes miss = 1 if finish > deadline for every policy; the kernel value is kept as `miss_kernel` and not used in analysis |
| L-32 | Adaptive agent runs without the machine flag | The agent's `QemuBridge` ignores `qemu_extra`, so it uses the default machine and CPUS=1 | T-59 is a CPUS=1 result only |
| L-33 | Gantt x-axis is the trace sequence number | Bar lengths in the Gantt charts count trace events, not ticks, so they do not show elapsed time | Read finish times from the `RESULT` line, not from the chart |
| L-34 | An existing test writes into `logs/` | `test_execfail_consumes_done_and_prompt` creates `logs/*deadbeef.run.raw` files when the test suite runs; they are not QEMU evidence | Ignore those files as evidence; deselect the test when `logs/` must stay unchanged |
