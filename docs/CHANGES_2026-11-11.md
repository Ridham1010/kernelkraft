# Changes of 2026-11-11 (post-audit fixes)

Every file in this bundle is a complete replacement for the file at the same
path. `xv6-public/wftest.c` and this note are new.

## Kernel

| # | Problem | Fix | Where |
|---|---|---|---|
| 1 | Kernel booted in round-robin, so donation was off unless `schedctl edf_donate` ran first | `DEFAULT_POLICY 2` in `sched_params.h`; rr and edf stay selectable | `sched_params.h`, `proc.c` (`sched_policy`) |
| 2 | A second process could join a workflow only on the exact tick the first one called | A later caller joins and takes the workflow's existing absolute deadline | `proc.c` `sys_setworkflow_impl` |
| 3 | A refused admission left the workflow slot allocated, blocking that wid until reboot | Admission is decided first; the table is written only on success | `proc.c` `admission_reason_locked`, `sys_setworkflow_impl` |
| 4 | `wid >= 8` refused; a 9th process with a deadline refused | Table is searched by wid, so any positive wid works (`NWF 16` live workflows); `MAX_URGENT 64` (= `NPROC`). `MIN_SLACK 20` is unchanged | `sched_params.h`, `proc.c` `wf_find_locked`, `wf_free_slot_locked` |
| 5 | A process that had missed its own deadline ignored a live donation | `effective()` drops only the process's own deadline after a miss | `proc.c` `effective` |
| 6 | `fork()` did not count the child as a workflow member, so the slot was freed while members were alive | `fork()` increments `nmembers` under `ptable.lock` | `proc.c` `fork` |
| 7 | Leaving policy 2 left stale `donated` values in use | `sched_setpolicy()` withdraws all donations when leaving policy 2 and rebuilds them when entering it | `proc.c` `sched_setpolicy`, `clear_donations_locked`; `sysproc.c` `sys_setsched` |
| 8 | 2 KB event arrays on the 4 KB kernel stack | `DONATION_EVENT_MAX 32` (512 bytes); unused array in `pipe_wait_end` removed | `sched_params.h`, `proc.c` |
| 9 | `struct pipe` did not record the writer side (handout item 3) | `struct pipe.writer` is set by `pipewrite()`. If the recorded writer still holds the write end it alone receives the donation; before the first write every write-end holder does | `pipe.c`; `proc.c` `donation_target` |
| 10 | A reader that blocked before the other process was forked never donated to it (seen as a missing `donate: cycle` on CPUS=3, L-29) | `fork()` runs the donation walk for any urgent reader already asleep on a pipe whose write end the child inherits | `proc.c` `fork` |

## Test programs

In `donate5`, `donatetest`, `cycletest` and `killtest` the parent used to call
`setworkflow` before forking, so every child, including the hog, inherited
the deadline and donation was never needed. Now only the process that is
meant to be urgent calls it:

- `donate5`: only stage 5 has a deadline; the hog is forked first, holds no
  pipe end and runs until the chain has finished. Prints `finish=`.
- `donatetest`: only the final reader has a deadline.
- `cycletest`: only one of the two processes has a deadline.
- `killtest`: the two donors join workflow 1 on different ticks; the test
  now fails if the donation disappears after the first kill.
- `wftest` (new): refused admission leaves no slot, a later joiner shares
  the deadline, a large wid is accepted, a workflow survives its creator.
